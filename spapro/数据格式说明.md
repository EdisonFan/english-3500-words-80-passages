# spa/data/p*.json 数据格式说明

> 本文档描述 `spa/data/p01.json` ~ `p80.json` 的数据结构规范，供后续维护参考。
> 对应的 `Passage_XX/学习助手_v2.html` 内嵌了同结构的 dict（JS 对象字面量），修改时需同步。

---

## 顶层结构

```jsonc
{
  "id": 3,                    // Passage 编号（整数）
  "stats": {
    "words": 256,             // 词汇总数
    "core": 73                // 核心词数
  },
  "paragraphs": [             // 段落数组
    {
      "num": "01",            // 段落编号（字符串，两位补零）
      "en": "{technology} {use} {in} {class}",
                              // 英文原文，教学单词用 {word} 标记高亮
      "cn": "<u> 课堂上 </u> <u> 科技产品 </u> 的 <u> 使用 </u>"
                              // 中文翻译，对应词用 <u> </u> 标记
    }
  ],
  "vocab": [                  // 词汇数组（见下方详细说明）
    ...
  ]
}
```

## vocab 数组元素结构

```jsonc
{
  "word": "permit",           // 单词原形（词形还原后的 lemma）
  "lemma": "permit",          // 规范词头；可省略，默认等于 word
  "kind": "word",             // 词条结构类型："word"=单词 | "phrase"=短语 | "proper_noun"=专名 | "abbrev"=缩写
  "type": "outline",          // 词汇类型："outline"=大纲词 | "core"=核心词
  "ctx": "被允许",            // ★上下文释义（重点字段，见下方规范）
  "forms": [                  // 文中可能出现的表层形式；用于 {permitted} 命中 permit
    {
      "surface": "permitted", // 文章中花括号里的实际形式
      "tag": "past_participle"
                              // 变形标签，如 plural / third_person / past / ing / comparative
    }
  ],
  "phonetic": "[pəˈmɪt]",     // 音标
  "memory": [                  // 词条级记忆信息；无则省略或 []
    "词根记忆：per（始终）+mit（送）→始终送出去→允许"
  ],
  "defs": [                   // 词典释义（完整，可含多个词性）
    {
      "pos": "v.",            // 词性
      "meaning": "（permitted, permitted, permitting）许可，允许",
                              // 释义（可含英文变形说明）
      "extras": [             // 义项级扩展信息；无则省略或 []
        {
          "type": "col",      // 类型（见下方枚举）
          "label": "搭",      // 中文标签
          "items": [          // 统一使用数组，哪怕只有一条
            "permit doing sth. 允许做某事"
          ]
        },
        {
          "type": "ex",
          "label": "例",
          "items": [
            "All the assignments will be submitted online. 所有作业都将在网上提交。"
          ]
        }
      ]
    },
    {
      "pos": "n.",
      "meaning": "许可证，执照"
    }
  ]
}
```

> 历史字段：旧数据中的顶层 `extras` 和 `words` 属于待迁移字段。新数据不再新增这两个字段。

## ★ ctx 字段填写规范（重要）

`ctx` 是 **context（上下文释义）** 的缩写，表示该词在**当前文章语境**下最贴切的中文意思。

英文原文中 `{...}` 标记的是**当前需要解释的表层单位**，可以是单词，也可以是短语：

- 单词变形：正文保留 `{roommates}`，词条使用 `"word": "roommate"`，并在 `forms` 中登记 `"surface": "roommates"`
- 短语整体承担语义：正文应标为 `{speak up}`，词条使用 `"word": "speak up"`、`"kind": "phrase"`
- 不要把短语义塞进单个单词的 `ctx`。例如 `speak up for yourself` 中，`speak up` 是“为自己发声/明确表态”，`speak` 本身仍是“说，讲；谈话；发言”

### ✅ 正确做法

| 场景 | 示例 | ctx 值 |
|------|------|--------|
| 动词在文中有特定用法 | "take **notes**"（记笔记） | `记` |
| 动词被动语态 | "will be **permitted**" | `被允许` |
| 名词特定含义 | "skill **set**" | `（一）套` |
| 固定搭配中的含义 | "**cast** your eye over" | `浏览` |
| "lose **sight** of" | | `忽视` |
| 短语整体承担含义 | "**speak up** for yourself" | `为自己发声，明确表态` |
| 复数/变形命中原词条 | "**roommates**" → roommate | `室友` |
| 功能词无实义（代词/连词等） | that / so / if | `/` |

### ❌ 错误做法

| 错误类型 | 示例 | 原因 |
|----------|------|------|
| 填英文变形形式 | `（permitted` | 完全不是中文释义 |
| 堆砌全部词典释义 | `拿走；携带；采取；花费；接受；记录` | 不是上下文最贴切的单一意思 |
| 保留英文变形前缀 | `（permitted, permitted, permitting）许可，允许` | 冗余，前缀应由 defs 字段承担 |

### 填写要点

1. **必须看上下文**：从 `paragraphs` 中找到该词的实际用法，再选最贴切的意思
2. **精简为单一释义**：一个词可能有多个意思，ctx 只填本文中用的那个
3. **纯中文**：不混入英文变形说明（变形信息属于 `defs.meaning` 字段）
4. **功能词**：代词、连词、冠词等无实义时填 `/`

## word / lemma / kind / forms 规范

### word

`word` 是当前词条的主 key，也是词表卡片显示的主要形式。它可以是单词，也可以是短语。

```json
{ "word": "roommate", "kind": "word" }
{ "word": "speak up", "kind": "phrase" }
```

### lemma

`lemma` 是规范词头。普通单词通常与 `word` 相同；短语通常也是短语原形。为兼容旧数据，缺省时视为等于 `word`。

### kind

`kind` 表示词条结构类型，建议使用以下枚举值：

| kind | 含义 | 示例 |
|------|------|------|
| `word` | 单词 | `roommate` |
| `phrase` | 短语/短语动词/固定表达 | `speak up` |
| `proper_noun` | 专名 | `South West London` |
| `abbrev` | 缩写 | `DIY` |

### forms

`forms` 用来登记文中出现、但不等于 `word` 的表层形式。渲染时应先匹配 `word`，匹配不到再匹配 `forms[].surface`。

```json
{
  "word": "roommate",
  "lemma": "roommate",
  "kind": "word",
  "forms": [
    { "surface": "roommates", "tag": "plural" }
  ]
}
```

常用 `tag` 建议：

| tag | 含义 |
|-----|------|
| `base` | 原形 |
| `plural` | 名词复数 |
| `third_person` | 动词第三人称单数 |
| `past` | 过去式 |
| `past_participle` | 过去分词 |
| `ing` | 现在分词/动名词 |
| `comparative` | 比较级 |
| `superlative` | 最高级 |

## defs / memory / extras 规范

### memory

`memory` 是词条级字段，用于放构词法、词根记忆、联想记忆等不属于某个具体词性的内容。

```json
{
  "word": "apologize",
  "memory": [
    "词根记忆：apo（远）+log（说话）+ize（做）→觉得过意不去，远远地说话→道歉"
  ]
}
```

### defs

`defs` 是义项数组。每个义项至少包含：

```json
{
  "pos": "vi.",
  "meaning": "道歉"
}
```

如果搭配、例句、用法说明只服务于某个义项，应放在该义项的 `extras` 下。

```json
{
  "pos": "vi.",
  "meaning": "道歉",
  "extras": [
    {
      "type": "col",
      "label": "搭",
      "items": [
        "apologize (to sb.) for (doing) sth. 因（做了）某事（向某人）道歉"
      ]
    },
    {
      "type": "ex",
      "label": "例",
      "items": [
        "You don't need to apologize for such a minor slip. 你不需要为这样一个小失误道歉。"
      ]
    }
  ]
}
```

### defs[].extras

`defs[].extras` 是义项级扩展信息。`items` 必须是字符串数组；只有一条也写成数组，方便前端渲染和数据库导入。

不再使用顶层 `extras`。旧顶层 `extras` 迁移规则：

- `type: "mem"`：迁移到顶层 `memory`
- `type: "col"`、`type: "ex"`、`type: "usage"`、`type: "拓"`：迁移到最相关的 `defs[].extras`
- 无法判断具体义项时，先迁移到第一个主要义项，并保留原顺序

### 废弃 words

旧数据中的 `words` 多数只是顶层词条的重复副本。新结构中删除 `words`，弹窗和词表都直接使用顶层 `word`、`phonetic`、`memory`、`defs`。

如果将来需要表达词条之间的关系，不要恢复内嵌完整词条副本，应另设轻量关系字段或数据库关系表，例如：

```json
"related": [
  { "word": "speak", "relation": "base_word" }
]
```

## defs[].extras.type 枚举值

| type | label | 含义 | 示例 |
|------|-------|------|------|
| `col` | 搭 | 搭配（collocation） | `take notes做笔记` |
| `ex` | 例 | 例句（example） | `All the assignments will be submitted...所有作业将...提交。` |
| `usage` | 用 | 用法说明 | `常用于被动语态` |
| `拓` | 拓 | 拓展（衍生词） | `borrow*（v. 借用）` |

## HTML 内嵌 dict 说明

`Passage_XX/学习助手_v2.html` 中内嵌了与 JSON 同构的 dict（JavaScript 对象字面量格式），用于离线加载。

**格式差异**：
- JSON：`"permit": {"ctx": "被允许", "type": "outline", ...}`（标准 JSON，key 有引号）
- HTML：`"permit":{ctx:"被允许",type:"outline",...}`（JS 对象字面量，key 无引号）

**修改原则**：改 JSON 时必须同步改对应 HTML，保持两者一致。

## 历史踩坑记录

### 2026-06-23：批量正则清理导致 JSON 结构损坏

**问题**：用正则 `("ctx":\s*")（[a-zA-Z][^）]*）` 批量去除 ctx 前缀时，`[^）]*` 会匹配换行符，导致贪婪地跨行匹配到下一个 `）`，把中间的 `phonetic`、`defs` 等字段全部吞掉，JSON 结构损坏。

**教训**：
1. **不要用文本正则批量修改 JSON**，应使用 `json` 模块解析后修改再写回
2. 批量修改后必须用 `json.loads()` 校验文件有效性
3. `ctx` 值需要人工判断上下文，不能机械处理
